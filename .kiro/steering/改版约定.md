# 本项目硬约定（2026 招新版改版期）

完整计划与进度在 `docs/2026改版计划.md`，**开工前先读它确认当前进行到哪个任务**。这里只放「不知道就会写错」的部分。

## 技术栈边界

Django 5.2 + Python 3.12（本机是 3.11.15，全局装了 Django 可直接用，无 venv）。生产 PostgreSQL 16 + Docker Compose，服务器 2 核 1.6G，`deploy.sh` 在其上构建镜像。

**无 Node 构建链**。第三方库以压缩产物提交进 `app/static/vendor/`，改版本号后跑 `python scripts/vendor_sync.py`。开发工具（playwright 等）不要写进 `app/requirements.txt`。

## CSS 三层，改之前先想清楚放哪层

| 文件 | 范围 | 判据 |
| --- | --- | --- |
| `tokens.css` | 令牌、`@font-face`、reset、基础元素、焦点环、View Transitions | 「没有归属于任何组件」的东西 |
| `core.css` | 全站组件 | 内页也会用到 |
| `home.css` | 首页分镜 | 选择器只出现在首页 |

加载顺序即层叠顺序，`home.css` 只在首页加载。**颜色、圆角、缓动、时长一律用令牌**，不要写字面值。缓动只有 `--ease-out` / `--ease-rise` / `--ease-damp` 三条，不要发明第四条。

一个组件开始被第二个页面用，就把它整份搬到 `core.css`（配套 JS 搬到 `site.js`），**不要复制第二份** —— 两份实现必然漂移。倒计时就是这么从 `home.css`/`home.js` 搬到 `core.css`/`site.js` 的。作品墙 / 荣誉墙 / 团队页起初各写了一份几乎逐字相同的 hero 和空态，Task 18 才合并掉 —— 那三次「就这一页，先复制一下」加起来是 189 条重复声明。

## 内容页是拼出来的，不要新画

`core.css` 的「内页通用」段是「一个内容页由什么组成」的唯一定义。**新页面从这里拼，不要再定义自己的页头/卡片/药丸/空态：**

| 共用件 | 用法 |
| --- | --- |
| `.page-hero.nf-scope` | 列表页页头横幅。强调色只改一个变量：`style="--hero-accent: var(--copper-2)"`。里面用 `.nf-eyebrow` + `h1`（带 `<span class="accent">`）+ `.page-hero-sub` + 可选 `.page-stats` |
| `.page-head` | 详情页 / 表单页那种不该压一条暗场横幅的场合 |
| `.card` / `a.card` + `.card-link` | 卡片盒子（描边、圆角、hover 抬起）。各页只补内部排版，**不要再写 border/radius/background** |
| `.pill-row > a.pill` | 筛选药丸。状态类是 `.is-current`（不是 `.active`）。`.pill b` 是 mono 计数 |
| `{% include "includes/pager.html" with page=page %}` | 分页。只有一页时整块不渲染，调用方不用包 `{% if %}` |
| `{% include "includes/empty_state.html" with icon= title= body= cta= cta_url= %}` | 整页空态 |
| `.inset-empty` | 面板或表格里的小空态（比整页空态轻一档） |
| `.table-panel` / `.table-sub` / `.row-actions` | 表格外壳、单元格第二行小字、行末操作列 |

- **翻页一律走 `includes/pager.html`**，它用 Django 5.1+ 的 `{% querystring %}` 从 `request.GET` 出发只覆盖 `page`。别再自己拼 `?page=N&category=...` —— 抄漏一个参数就是「翻到第二页筛选没了」，页面照常渲染、控制台干净。
- **切换筛选的链接要显式 `page=None`**：`{% querystring category=value page=None %}`。不清的话在第 3 页换个分类会落到一片空白上。
- **空态必须给下一步。**「暂无内容」是死胡同，读者到这里就走了。和 `includes/empty_board.html` 是两件事：那份是**图片**缺位的占位框，这份是「列表没条目」。
- `.dash-*` 只定义在 `dashboard.css` 里，而**前台页面不加载它**（`base.html` 只 link `tokens.css` + `core.css`）。前台模板写 `.dash-table-wrap` 的后果是那一块一点样式都没有 —— 表格不能横向滚动、按钮不排成一行 —— 而页面渲染正常、控制台干净。`ContentPageConventionTests` 扫全部前台模板拦住这条。
- 加了新的列表页就把它加进 `core/tests.py` 的 `LIST_TEMPLATES`，那几条扫模板的断言负责让收敛不被下一次复制粘贴退回去。

## 主导航的条目数量是硬约束

顶层平铺过 10 条，实测「会标 160 + 链接 726 + 右侧账号区 284 + 两道 30px 间隙」= 1230，而容器最宽 1240 —— **只剩 10px**。用户名长一点就把链接挤到自己内部换行（「新生指 南」裂成两行），而且汉堡菜单当时要到 720px 才接手，721~1090px 这一整段（平板、小笔记本）导航都是坏的。

- **想加入口，往折叠组里加，不要往顶层加。** 顶层现在 5~6 条，`NavigationTests.test_top_level_item_count_stays_small` 卡在 6。
- 折叠组用**原生 `<details>` + `<summary>`**（`data-nav-group`）：没有 JS 也能展开、键盘可达、读屏认得。`site.js` 只加「同时只开一个 / 点外面关 / Esc 关并把焦点还给 summary」。**不要改成「按钮 + JS 加类」** —— 脚本挂了整组链接就不可达。
- 汉堡断点是 **1024px**，在 `core.css` 那个 `@media (max-width: 1024px)` 块里，**那个块只放导航**；版面的窄屏改造在 720px 块里。混在一起改断点会让公告在 1024px 变单列、活动卡片竖排。
- 窄屏面板靠 `.nav-inner` 换行实现（链接区和账号区各占一整行），不是绝对定位。两个必须记住的细节：`row-gap: 0`（`gap: 30px` 换行后会变成行间距，凭空多出 60px 把面板撑出屏幕）；`.nav-burger { order: 1 }`（它在 DOM 里最后，不排序就被挤到账号按钮下面去）。
- 面板**刻意不占满整屏**（链接区 `max-height: calc(100vh - 240px)` 自己滚），留一截页面出来 —— 触屏上「点外面关闭」是唯一顺手的关法，Esc 在手机上不存在。

**和工具类叠加时只写 `background-color`**，不要用 `background` 简写：`.rec-hero { background: var(--black) }` 会把同一元素上 `.nf-scope` 的示波器网格 `background-image` 整个重置掉，网格凭空消失且不报错。

重构 CSS 后用 `python scripts/css_audit.py --before X --after Y` 证明没丢规则。

## 动效必须走 motion-core

页面级动效不要自己 `new Lenis` 或自己注册 ScrollTrigger，统一用 `ESTA.motion.scene(name, fn, opts)` 注册，内核负责 try/catch 隔离、`reduced` 跳过、WebGL 门控。`ESTA.motion` 暴露 `caps` / `EASE` / `DUR` / `gsap` / `ScrollTrigger` / `SplitText` / `lenis` / `scrollTo` / `once`。

**降级契约（最重要的一条）**：所有「先隐藏再动画」的 CSS 必须写在 `html.motion-ready` 之下。这个类只在 GSAP 就位后才加，否则动效库加载失败就是白屏。

按**能力**分支不按设备档次。移动端只要有 WebGL 就跑完整效果，只调 DPR 上限与几何密度。只有 `prefers-reduced-motion` 和 WebGL 不可用才降级。`saveData` 不降级动效，只影响视频是否自动播放。

## 跨页转场的命名元素契约

根级淡入淡出是纯 CSS（`tokens.css` 的 `@view-transition { navigation: auto }`），不用管。`app/static/js/view-transitions.js` 只做一件 CSS 做不到的事：把「列表里那张卡片的封面」和「详情页顶部那张大图」认成同一个东西，于是点进去时图片是长大的。

这一整套的失败模式**全是静默的** —— 名字重了、名字没摘、脚本晚一步挂上监听，浏览器一律「跳过转场、照常导航」，页面正常、控制台干净，只是那个效果压根没发生。所以下面每一条都有断言钉着。

- **`view-transition-name` 在一个文档里必须唯一，所以名字只能由 JS 在导航那一刻指派。** 列表页十几张卡片全命名会让浏览器直接跳过**整个**转场并报重名。模板里一个静态名字都不许写（`ViewTransitionMarkupTests` 扫全部模板拦住）。详情页也不行 —— 底部「还有这些」的推荐卡片同样带标记，点它时会和 hero 的静态名撞车。
- **转场结束必须把名字摘掉**（`transition.finished` 里摘）。留着的话下一次导航就重名，同样是静默跳过。
- 标记只有两个：列表侧 `<a data-vt-card href>` 里放 `data-vt-part="cover"`，详情侧 `data-vt-part="cover"` 且**不在**卡片里。配对判据就是「在不在 `[data-vt-card]` 里」，同一段代码两边通用。加新部位要同时补三处：模板的 `data-vt-part`、`view-transitions.js` 的 `PARTS`、`tokens.css` 的 `[data-vt-name="x"]` 映射，少一处那一格就是静默无效。
- **`view-transitions.js` 在 head 同步加载，不能 defer/async。** `pagereveal` 在新文档第一次渲染前触发，defer 与它的先后没有保证，慢一步监听器就没挂上。这是刻意的，别「顺手优化」成 defer。
- **只配封面，不配标题**（18px → 50px 的文字形变会被拉变形，比直接淡入难看）；**无封面时不指派名字**（占位框两边形状一样，morph 没有信息量，反而让「缺图」看着像在动）。
- **不要在 `::view-transition-old/new(名字)` 上写 `animation: none` 或改 `mix-blend-mode`。** 配上对的一对靠 UA 的 `plus-lighter` + 组上 `isolation: isolate` 交叉淡入，不透明度相加恒为 1，本来就不会透出底下的页面。关掉之后既丢了过渡，也让 `document.getAnimations()` 再也看不到这两个伪元素 —— 而那是判断「配上对没有」的唯一硬证据。要改裁切只调 `object-fit` 与尺寸。
- 形变的时长要比根级淡入长一档。`--ease-rise` 是 expo-out、动作极度前置，`.35s` 的话 140ms 就走完九成，读起来是瞬切。封面组用 `--t-slow`。
- 全部逻辑包 try/catch：**转场是锦上添花，绝不能挡住导航。**

动了转场相关的任何东西（`view-transitions.js` / `tokens.css` 的 VT 一节 / 带 `data-vt-*` 的模板）就跑 `python scripts/check_transitions.py`。它的判据是**转场里 `::view-transition-old(名字)` 与 `::view-transition-new(名字)` 同时存在**，而不是「有没有动画」—— 没配上对时新元素会单独淡入，屏幕上仍然有动静、肉眼多半看不出差别。想肉眼看就 `--keep`，但**接着跑 `check_works.py` 之前要先不带 `--keep` 跑一次**把留下的公开作品清掉。

## 无障碍与性能：这一类故障不会自己暴露

鼠标能点、页面能看、控制台干净、既有脚本全绿 —— 而键盘走不通、读屏读不对、或者每个访客白下 750KB。所以下面每一条都有断言钉着，动了相关的东西就跑 `python scripts/check_a11y.py` / `check_perf.py`。

**判据一律是「渲染之后到底能不能用」，不是「标记写对了没有」。** 真实教训：消息提示（`.messages-wrap`）原来放在 `<main>` 外面，吃不到 `.site-main` 那份 `padding-top: 74px`，整条被固定导航盖住 —— 「保存成功」「验证码已发送」一个都看不见，而 `check_register.py` 与 `check_media_center.py` 里「给出了反馈」那两条断言一直是绿的，因为它们读 `textContent`，文字确实在 DOM 里。**「这一块给了反馈吗」要连位置一起验**：顶边 ≥ 导航底边，且 `elementFromPoint` 命中它自己。

- **`<body>` 里第一个可聚焦元素必须是 `.skip-link`。** 固定导航有十几个可聚焦项，没有它键盘与读屏用户每一页都要先 Tab 穿过整排。落点 `<main id="main" tabindex="-1">` —— 只给 id 的话部分浏览器只滚动、不移动焦点，跳过去再按 Tab 又回到导航里。
- **要藏文字给读屏看就用 `.sr-only`**（`clip-path` + 1px 尺寸），**绝不用 `display: none` / `visibility: hidden`** —— 那两种写法读屏软件也读不到，等于这段文字压根没写。
- **状态不能只靠颜色。** `.pill.is-current` 改的只有 border/background/color，所以当前态必须同时给 `aria-current="page"`，而且**和类名共用同一个 `{% if %}`**（`{% if c %}class="pill is-current" aria-current="page"{% else %}class="pill"{% endif %}`）—— 条件抄两遍迟早只改一处。全站 14 处药丸都是这个写法。
- **强调色分暗底 / 白区两支。** `--accent` (#0da9cd) 在白区 `--paper` 上只有 **2.61:1**，连大字要的 3:1 都不到（暗底上它是 11:1 以上，所以「一个强调色两边通用」这个直觉是错的）。白区用 `--accent-ink`。第三档文字用 `--muted-dim`（5.05:1），**不要再写 `#6b7280`**（4.21:1，`RETIRED_COLORS` 拦着）。
- **标题层级不跳级。** `<summary>` 不是标题 —— 折叠块里的第一层小标题接的是外面那个 h2，写 h4 就跳了一级。字号由 CSS 定，和标签级别无关。卡片组件被多个页面复用时不要为了层级去改它（`work_card.html` 的 h3 在首页分镜 07 与详情页底部都是对的），给缺那一级的页面补一个 `<h2 class="sr-only">` 更省事也更对。
- **点击入口必须是原生 `<button>` / `<a>`**，不要把监听器只挂在外层 `div` 上 —— 冒泡让鼠标和键盘都「能用」，但无障碍树里那一块没有角色，读屏软件读不出「这是可以按的」。真按钮是入口，div 只是给鼠标的大靶子。
- **首屏之外的图一律 `loading="lazy"`，所有图都写 `decoding="async"`**；但**不要为了防 CLS 补 `width`/`height`** —— 本项目的图占位靠 CSS `aspect-ratio`，而 `<img>` 上宽高都给确定值时 `aspect-ratio` 会被忽略，补了反而把占位搞坏。
- **重型库只能出现在真的用它的页面上。** three 一个人 750KB（module + core），只服务首页分镜 01。`check_perf.py` 对每个内页断言「没拖进 three」，并断言**减动效偏好下首页也不下它**（把 `import()` 提到能力判断之前，降级用户照样付全部流量 —— 这条最容易悄悄坏掉）。
- head 里**只允许 `view-transitions.js` 一个同步脚本**（理由见上一节），其余一律 `defer`。新加脚本忘了 defer 是最常见的一次性退步，`DeployPerfContractTests` 拦着。

### 字体：缺字是静默故障

`--font-display`（思源 Heavy）是按**模板里出现过哪些汉字**子集化的。新文案带进新字时那些字会按 `font-display: swap` 回退系统黑体 —— 一行标题里混着两种字重两种字形，而页面不报错、`collectstatic` 照常过。**改了模板文案就跑 `python scripts/check_fonts.py`**（拿字库 cmap 逐字对模板用字）。真实教训：Task 10~19 加完文案后 1097 个字里缺了 274 个（25%），一直没人发现。

缺字就重跑 `python scripts/build_fonts.py <JetBrainsMono[wght].ttf> <SourceHanSansCN-Heavy.otf>`（源文件下载地址在它的文件头；需要 `pip install fonttools brotli`，**开发工具，不要写进 `app/requirements.txt`**）。两个字体都必须在 `base.html` 里 `preload`，否则浏览器要等 CSS 解析完才发现它们，首屏那条大标题会先用系统黑体画一遍再跳。

`collect_cjk_chars()` 会先整块摘掉 `{% comment %}` 与 `<!-- -->`：本项目模板注释又长又全是中文，而注释一个字都不渲染 —— 不摘就白白多 125 个字、33KB，而且让上面那条检查变成在要求「注释里的字也得在字库里」。

### nginx 那几条不生效也不报错的

改了 `ops/nginx/heuesta.cn.conf` 要 `ops/deploy.sh` 才到生产（它自己跑 `nginx -t`）。

**`add_header` 不累加、只覆盖**：一个 `location` 里只要出现了 `add_header`，就不再继承上层的任何 `add_header`。安全头写在 `server` 层会被带自己 `add_header` 的 `/static/` 块整个丢掉 —— 要哪层生效就写在那一层，并且加 `always`（否则 4xx/5xx 上没有）。

- **`gzip_types` 要同时列 `text/javascript` 与 `application/javascript`。** `.js` 的默认 MIME 在 nginx 上游 1.21.1 从后者改成了前者，而各发行版跟进时间不一样。命中的话**所有 JS 原样过网**，页面照常能用、日志里什么都没有。（实测生产的 Ubuntu nginx/1.24.0 仍是 `application/javascript`，本来就在压缩 —— 所以这条是防御性的。**压没压不要读配置猜，跑 `ops/verify.sh`。**）
- 前面挂着 EdgeOne，必须 `gzip_vary on`。
- **`expires` 和 `add_header Cache-Control` 不要同时用**：会发两条 Cache-Control 头，各家 CDN 取哪条不好说。只留 `add_header` 那一条完整的。

## 会标只有一份几何

`app/static/brand/logo-mark.svg` 是唯一事实来源，模板、加载动画、three.js 的 `SVGLoader` 都读它。模板里用 `{% load brand %}{% inline_svg "brand/logo-mark.svg" class="..." %}`，不要用 `<img>`（`currentColor` 会失效，也无法逐段动画）。

改这个文件后必须跑 `python scripts/verify_logo.py`。两条铁律：**任何属性都要带值**（独立 `.svg` 走 XML 解析，无值属性让整图解析失败）；**走线不能画到焊盘圆心**（会填掉内孔，焊盘变实心点），止于环外缘半径 14。

## 素材缺位是常态，不是异常

协会现在缺图，而且会缺一段时间。所有可能缺图的位置都走素材槽，渲染成设计过的「空焊盘」——虚线 + 四角定位标 + 拍摄要求，站务登录时多一个上传入口。**不要**用 `<img>` 直接引一张不存在的图，也不要临时找图凑数。

素材槽已就绪（Task 7），用法：

```
{% load slots %}
{% slot "home.gallery.group" css_class="nf-tile" eager=forloop.first %}
```

**槽位声明在 `app/core/slots.py`，内容在 `MediaSlot` 表。** 新增展示位的步骤是：先在 `slots.py` 里加一条 `SlotSpec`（label / ratio / brief 三样都必填，brief 要写「要拍什么」因为它会直接显示给用户看），再在模板里 `{% slot %}`。两边不一致会被 `SlotRegistryTests` 扫出来。

- `ratio` 必填且要准，它负责在图片下载完成前把版面高度占住。
- `fallback` 只放**协会自有的、已提交进仓库的**照片；没有合适的就留空显示占位框。
- **不是所有图片都该进素材槽。** 判据是「这里缺一张我们自己的照片吗」。参考插图（元件棚拍、软件界面截图、示意图）不该进：它们不缺、棚拍本来就比抓拍更能说明问题，而且槽位是 `object-fit: cover` 铺暗底，白底棚拍现有的处理会丢掉。真把 69 张图鉴改成槽位，驾驶舱的缺图清单会被淹掉，真正缺的那几张反而看不见。新生指南就是这么判的（见 `core/slots.py` 的「新生指南 · 现场照」注释）。
- **数据库驱动的图（作品封面等）也不走槽位**：槽位是「模板里固定的那一格」，行数不定的内容用自己的 `ImageField`。但**缺图的样子要一致** —— 直接 `{% include "includes/empty_board.html" with label=... brief=... ratio=... %}`，那份标记就是槽位空状态用的同一份。
- `MediaSlot` 加字段要 bump `core:media_slots:v1`。
- 不要再用 `CarouselImage` 加新展示位，它已被取代、只等搬迁后删除。
- 改完跑 `python scripts/check_slots.py`；动了驾驶舱那一侧再跑 `check_media_center.py`；动了视频再跑 `check_video_slots.py`。

**视频槽是图片槽的超集**：`SlotSpec.kind="video"` 时 `image` 字段身份变成封面帧，另有 `video_mp4` / `video_webm`。只传封面就是一张静态图，不必为降级另备素材。`<video>` 上**不要写 `autoplay`** —— 播放由 `video-slots.js` 按能力决定（减动效偏好、省流都只显示封面，其余进视口才播）。省流只影响视频是否自动播，**不降级页面动效**。

站务在 `/dashboard/media/`（`dashboard:media_slots`）填图。**这个 URL 名字不要改** —— 占位框靠 `reverse` 它决定要不要显示上传入口，改名会让入口静默消失。

`ImageField` 若用 `width_field/height_field`，那两个字段必须 `null=True`：没有文件时 Django 会显式把它们设成 `None`，`default=0` 拦不住，插入时 NOT NULL 失败。测试里要图就用 `core.tests.make_png()`，不要手写 base64 常量（CRC 常是坏的，能存进库但过不了表单校验）。

PowerShell 里 `命令 2>&1 | Select-String` 会把 stderr 变成错误记录、让 `$LASTEXITCODE` 非 0，看着像失败。要判断真实退出码就别拼管道。**这几个浏览器脚本干脆别接任何管道**：`| Out-File` 会把它们吊死到超时，`> file` 又写成 UTF-16、读出来一片乱码。直接看输出。

**浏览器检查脚本一次只能跑一个**：它们共用固定端口 8799，而 `DevServer` 有「已在监听就复用」的逻辑，并行跑会互相把服务器关掉、双双吊死。`node scripts/motion_smoke.js` 必须在仓库根执行（按 cwd 解析路径）。

检查脚本里要造数据就直接调 ORM，但 Playwright 同步 API 在 Django 看来是异步上下文，会抛 `SynchronousOnlyOperation` —— 脚本顶部加 `os.environ.setdefault("DJANGO_ALLOW_ASYNC_UNSAFE", "1")`。造「服务端缓存过的数据」（招新状态等）必须在 `DevServer` 起来**之前**做，dev 是进程内 LocMem 缓存，外部脚本没法让它失效。

脚本改了开发库状态就要**在开头和结尾都摆回去**：崩在中间会留下一个奇怪的库，下次跑到别的断言处莫名失败。建测试数据先按名字删再建，`create` 不去重，跑几次堆出一串同名记录后按名字 `get()` 直接抛 `MultipleObjectsReturned`。

两个 Playwright 陷阱：`page.fill()` 填不了被分步藏起来的字段（拒绝操作不可见元素，30 秒超时），要测服务端往返就用 `evaluate` 灌值；`evaluate(form.submit())` 后不要接 `wait_for_load_state`，会和导航赛跑抛「Execution context was destroyed」，用 `with page.expect_navigation(...)` 包住。

**要拍一个短动画的中间态，不要靠「等 N 毫秒」赛跑，把动画冻住。** `document.getAnimations()` 里挑出目标，`pause()` 再设 `currentTime`，然后截图。跨页转场是最极端的例子：它在新文档第一次渲染时才起跑，而 `Page.captureScreenshot` 自己也要花时间 —— 十次里九次拍到已经落定的终态，而那看着就像「压根没有这个动画」。冻住之后还能顺手断言中间那一帧的几何值介于起止之间，比看图更硬。（`shoot.py --at MS` 适用于起点确定的场合，起点本身不确定时只能冻。）

**定位按钮要用专用 data 钩子**，不要 `page.click("button[type=submit]")`。驾驶舱一页往往有很多小表单各带提交按钮，其中带 `onsubmit="return confirm()"` 的会被 Playwright 自动 dismiss —— 于是不提交、不导航、后面的断言莫名失败，而看不出是点错了按钮。模板里加个 `data-honor-save` 之类的钩子，脚本按它点。

**搬动一段逻辑后，grep 谁在断言「它不在时的样子」**。倒计时从 `home.js` 搬到 `site.js` 之后，`check_hero.py` 那条「脚本挂了不能露出一排 `--`」还在把 `js/home.js` 拦成 404 —— 拦了个不相关的文件，那个场景根本没被模拟到，断言却照样打勾。降级断言天生容易假通过。

**「某个值应该变化」的断言在「什么都没发生」时同样成立**，等于没写。写过一条「展开折叠块后进度比例应该变小」，而脚本压根没重算时比例也不变 —— 前后都是 38.6%，一路绿灯。要断言就拿 DOM 里的值和**现场重新算一遍**的期望值比。

**断言之前先确认被测的东西真的出现了。** 两次踩到同一个形状：① 验「筛选之后翻页筛选还在」，而种子数据筛完只剩 7 条 < 每页 12 —— 分页控件整块不渲染，取「下一页」拿到 `None`，断言空跑。② 数「顶层导航条目」时正则把折叠菜单里的二级链接也数进来，得到 12 个 —— 正好是收敛之前的规模，于是断言永远通过。**造数据时要保证边界条件成立，选择器要收窄到自己测的那一层。**

平滑滚动（`html { scroll-behavior: smooth }`）跨几千像素要一秒多，固定 `wait_for_timeout(500)` 会在半路采样、读到「跳歪了」的位置。轮询到 `scrollY` 不再变化再断言。

## 写命令的规矩

逻辑放进 `scripts/*.py`，用 `python scripts/x.py` 调用。**不要写超长内联 PowerShell 管道**：Kiro 按子命令拆分做权限匹配，长管道会产生一堆碎片规则并反复触发用户确认，同时还会踩引号嵌套和 GBK 乱码。

PowerShell 里换行分隔的多条命令**只执行第一条**，要用分号。Python 脚本里加 `sys.stdout.reconfigure(encoding="utf-8")`，否则管道输出中文乱码。

**整份写一个文件之前先确认它存不存在**。以为 `app/news/forms.py` 是新文件、直接写下去，把里面已有的 `PostForm` 抹掉，全站 `ImportError`。已存在的文件一律用增量编辑。真覆盖了就 `git show HEAD:路径` 取回原文，事后 `git diff --numstat` 核一遍增删行数对不对。

## 几个会静默出错的地方

- Django 的 `{# #}` **只支持单行**。跨行注释用 `{% comment %}`，否则注释里的模板标签会被真的执行。
- `SiteConfig` 加字段必须 bump `core:site_config:v3` 的版本号（生产是 DatabaseCache，缓存 pickle 实例，TTL 1 小时）。
- 新增 ES module 后本地跑一次 `check_static_pipeline`：相对 import 指向不存在的文件会让 `collectstatic` 直接中断部署。**动态 `import()` 用裸标识符**（走 importmap）本来也会中断部署，`config/storage.py` 已覆盖掉，别把那段覆盖删了。
- 加载动画期间 `html.esta-pre-lock body { overflow: hidden }` 会让全页所有 `position: sticky` 失效。写滚动断言前先等 `html:not(.esta-pre-lock)`；要复用这个锁做弹窗也记住这条。
- `subprocess` 起长命进程时日志落文件，不要用 `PIPE` 挂着不读 —— 缓冲写满后子进程卡死在 write 上。
- **不要用 `el.innerHTML += el.innerHTML` 复制内容**。它重新解析整个子树，原有节点连事件监听器一起作废，但类名留着 —— 「先隐藏、等 JS 显示」的元素就此永久隐藏且不报错。用 `cloneNode(true)`，并把插入后要重新接线的逻辑做成可回调的函数（现有的是 `window.ESTA.hydrateImageFades(root)`）。
- 给图片挂 `load` 监听前先判 `img.complete`：已经加载完的图不会再触发事件，回调永远不来。
- **`<img>` 上的 `width`/`height` 属性会让 CSS `aspect-ratio` 失效**（宽高都是确定值时 `aspect-ratio` 被忽略）。为防 CLS 写了这两个属性，同一元素的 `aspect-ratio: 4/3` 就此静默失效 —— 一张 600x450 的图按 450px 高渲染，占掉半屏。要 `aspect-ratio` 生效就补 `height: auto`。
- **状态类不要配裸标签选择器**：`.hn-lv-national strong` 的特异度 0,2,0 压过 `.hn-title` 的 0,1,0，等级色染到了本不该染的奖项名上。收窄到具体组件（`.hn-stat.hn-lv-national strong`）或用直接子代（`> .hn-badge`）。
- `tokens.css` 有一条全局 `[hidden] { display: none !important; }`，**别删**。组件设了 `display: flex/grid` 就会盖掉浏览器给 `[hidden]` 的默认值，于是 `el.hidden = true` 完全没有效果而 JS 那边看起来完全正确。全站一堆「脚本按能力放出/收起」的元素靠它。
- flex 里居中一个可能比容器高的子项，用子项的 `margin-block: auto`，不要用容器的 `align-items: center` —— 后者在子项更高时朝两侧等量溢出，顶部那截跑到父盒外面直接看不见。
- flex 容器的 `gap` 在 `flex-wrap: wrap` 之后**也当行间距用**。`.nav-inner { gap: 30px }` 换行后每道行缝各吃 30px，汉堡面板凭空多出 60px、撑出屏幕。换行布局要显式 `row-gap: 0`。
- `flex-wrap` 之后哪个元素落在哪一行由 **DOM 顺序**决定。汉堡按钮在 DOM 里排最后，不给 `order` 就会被挤到最后一行去。
- `{% querystring %}` 直接读 `context.request` 属性。测试里要单独渲染含它的模板，得走 `render_to_string(..., request=)`，而那会跑全套 context processor —— `RequestFactory` 造的请求还要自己补 `request.user = AnonymousUser()`。
- 要响应「文档高度变了」，盯 `ResizeObserver(document.body)`，不要只监听 `details` 的 `toggle`：折叠块有 .45s 高度过渡，`toggle` 在 `open` 翻转那一刻就触发，那时高度还是 0，算出来是中间态且再没人重算。ResizeObserver 顺带覆盖图片陆续落地与字体 swap。
- 「读过的都保持点亮」这类**前缀语义**不能用 `IntersectionObserver`（它只回答「谁现在可见」，长区块滚过去后已读状态会被熄掉）。自己拿 `getBoundingClientRect().top` 和一条固定判定线比。

## 表单渐进增强只有一份实现

`app/static/js/form-enhance.js` 是全站唯一的分步 / 条件字段 / 确认回显实现，招新报名表与注册表单共用。要在新表单上用它，挂 data 属性即可，**不要再写第二份**（契约见那个文件的文件头）：

```
<form data-stepped-form>
  <ol data-step-dots><li>…</li></ol>
  <fieldset data-step>…</fieldset>
  <fieldset data-step>
    <dd data-review-for="email"></dd>      {# 提交前回显 #}
  </fieldset>
  <button type="button" data-step-prev hidden>上一步</button>
  <button type="button" data-step-next hidden>下一步</button>
  <button type="submit" data-step-submit>提交</button>
</form>
<div data-show-when="id_specialty=custom">…</div>   {# 条件字段，可单独用 #}
```

四条硬要求：

- 一张完整的表单、一次 POST。字段分到几个 `fieldset` 里，**默认全部展开**，没有 JS 也能填能交。
- **提交按钮始终在 DOM 里且始终可提交**。不要把「下一步」做成必经之路，也不要用 `disabled` 的提交按钮 —— 脚本判断写错一次，用户就彻底交不了表。收起来（`hidden`）和禁用是两件事。
- **不依赖藏起来的字段做原生校验**：浏览器对 `display:none` 里的 `required` 报「An invalid form control is not focusable」，有报错但界面上毫无提示，用户只看到点了提交没反应。所以 HTML 里**不要写 `novalidate`**（没有 JS 时原生校验是有用的），由脚本接管后自己打开；条件字段隐藏时连带摘掉 `required`。
- **服务端退回的错误必须能被看见**：出错字段可能在第二段，初始化要停在第一个带错误的段，否则用户看到一张「没有任何问题」的表。

服务端分步（多次请求 + 草稿存储 + 会话状态 + 回退处理）只在字段多到一屏放不下、且中途退出必须能续填时才考虑。

## 账号链路的外壳与约束

注册 / 登录 / 验证码登录 / 找回密码 / 完成页共用 `accounts/_auth_base.html`：三个平级栅格项（`.auth-head` / `.auth-panel` / `.auth-extra`），窄屏由 `grid-template-areas` 重排成「标题 → 表单 → 补充说明」—— 表单是这些页面的主要动作，不能被整个说明栏推到首屏之外。前缀 `.auth-*` 外壳 / `.reg-*` 注册三页 / `.lv-*` 等级阶梯；**旧的 `.auth-card` / `.auth-sub` / `.auth-links` 还有六个 Tier 2 页面在用，别删**。

- 这些页面一律 `@never_cache`（要 `no-store`，中间件只给 `private, no-cache`）。Django 自带的 `LoginView` 本身带，自己写的视图要自己加，漏一个不报错 —— `AuthPagesNoStoreTests` 逐个钉住。
- `?next=` 要一路带过每一跳（含通道选择页那种纯跳转页），统一走 `accounts.views._safe_next()`，**必须**过 `url_has_allowed_host_and_scheme`。
- 验证码字段用 `{% include "includes/field_code.html" with field=... purpose="register" %}`。`[data-code-msg]` 是 `auth-code.js` 找消息位的钩子 —— 没有它，服务端返回的「该邮箱已注册」这类原因一个都显示不出来。
- **每一态都要给出下一步**，不能有死胡同（注册完没有开放批次时走完成页，而不是把人丢到「招新通道暂时关闭」上）。
- Django 的 `UserCreationForm` 会给 `USERNAME_FIELD` 挂 `autofocus`。分步之后它在第三段里，autofocus 早于 `defer` 脚本生效、把页面滚到底部，脚本再收起段落 —— 打开就停在页面底部，控制台一声不响。已在 `BaseRegisterForm.__init__` 摘掉。

## 把成员信息放到公开页面上，必须本人同意

注册时那份隐私同意书写的是「身份核验、招新联系、账号安全」，**一个字都没提「公开展示在官网上」**。所以任何把某个具体成员摆到公开页面上的功能，都要一次单独的、明示的同意。

- 开关是 `User.show_on_team`，**默认 `False`**，唯一入口是本人的 `/accounts/profile/edit/`。站务和管理员**都不能代勾** —— 驾驶舱职位管理页只显示「谁还没勾」，压根不处理这个字段。要加新的公开展示位就复用这个开关，不要再造第二个。
- 公开页面上**不出现手机号、邮箱、学号、QQ**（隐私说明里写了这句）。要联系具体的人，一律指向招新 QQ 群。团队页有一条断言直接拿种子值去搜页面源码和可见文本 —— 这类泄漏发生时页面看起来完全正常，只有搜一遍才发现。
- 「谁上墙」的口径只有 `User.team()` 一处：激活 + 本人勾了 + **当前担任职位**。加消费者就用它，不要另写一遍 filter。
- 聚合数字（在册人数 / 覆盖学院数 / 跨越届数，`User.team_summary()`）不指向任何人，**不受这个开关约束** —— 一个人都没勾时它就是那一页的全部内容。
- 表单只对**有职位的人**显示这个开关（`ProfileForm.__init__` 里摘字段）：没职位的人不会上墙，给他一个勾了也没反应的开关就是坏界面。摘掉之后 POST 里塞上它也不生效，这一条有测试钉住 —— 否则「只对有职位的人显示」只是界面上的装饰。
- 自建职位（驾驶舱职位管理）**一律不授予 `grants_management`**。要站务权限就走等级变更，那条路有日志、有通知、有审计。`_RETURNING_POSITIONS` 里那五个是固定职位，不能改名或删除（`returning_review()` 按名字 `update_or_create`，改了名下一次审核会静默再建一个同义职位）。

## 钉住式分镜的两条硬要求

1. 钉住用 CSS `position: sticky`，不要用 ScrollTrigger 的 `pin`（它插 pin-spacer 改 DOM，和 Lenis 配合会抖）。
2. **窄屏必须换构图，不是缩小桌面版**。桌面两栏直接堆叠后内容会远超 100vh，标题被固定导航切掉、主体掉到屏幕外；而这件事在桌面尺寸下永远看不到，所以每个钉住区块都要有一条移动端断言：三块内容都落在导航底以下、视口以内。参考 `scripts/check_forge.py`。

## three.js 里踩过的形状问题

- 别用 `mesh.scale` 做动画：`applyMapping` 已经把 SVG→场景的归一化比例烘在里面，覆盖它等于把物体放大 216 倍。要动缩放就乘 `userData.baseScale`，或让几何以自身中心为原点、只用 `position` 定位。
- 带厚度的走线用**偏移带**（顶面/底面/两侧壁/两端圆帽），不要「线段盒 + 每顶点补圆柱」—— 后者在曲线段上共面重叠，渲染成一片麻点。
- 正面视角下完全平的金属面只采到环境贴图一个点，看着像刷漆。顶面法线沿宽度外倾（现取 0.26），并把细长四边形沿中线切开消除对角折痕。
- 当 `alphaMap` 用的画布，背景必须纯黑（只看绿通道，通道值就是不透明度）。要抠掉一块就用纯黑覆盖，别用 `destination-out`。
- 改了模板文案要重跑 `scripts/build_fonts.py`，中文子集是从模板扫出来的，不重跑新字会回退系统黑体。
- nginx 对 `/media/projects/` 与 `/media/resources/` 返回 403（会员私有文件，要经 `X-Accel-Redirect` 鉴权才发）。**任何公开可见的图都必须落在别的前缀下** —— 作品墙用 `works/covers/` 与 `works/shots/`（`Project.cover` / `ProjectShot`）。本地开发用 Django 自己服务 media，放错路径一切正常、上线才发现是一墙碎图，所以这条靠 `WorksMediaPathTests` 断言 `upload_to` 前缀守住。
- 表单里加文件字段要同时补三处：字段、模板的 `enctype="multipart/form-data"`、视图里的 `request.FILES`。漏任一个都不报错，只是文件永远存不上。
- `class Meta` 的类体看不见外层类的类属性（Python 的类作用域不参与嵌套查找）。`fields = SOME_TUPLE + OTHER` 这类常量放模块级。
- **`annotate()` 之后 `Meta.ordering` 静默失效。** `annotate(Count(...))` 会建 GROUP BY，而带 GROUP BY 的查询不再套用模型的默认排序 —— 生成的 SQL 里压根没有 ORDER BY（`qs.ordered` 也变成 `False`）。列表变成数据库返回的任意顺序，页面照常渲染、没有任何报错；要是还接了 `Paginator`，同一条记录会在两页里重复出现或者干脆消失。**用了 `annotate` 就把 `order_by` 显式写出来**，本项目已因此修过 5 处。
- 生产环境有一把能 root 登录 `123.57.6.128` 的 pem 密钥在仓库根目录。对生产的破坏性操作要先确认。

## 上线：本地写完不等于上线了

**`ops/deploy.sh` 是从 GitHub `main` 分支下载归档来更新代码的**（服务器直连 git 协议不通，走 codeload tarball）。所以：**没提交、没推到 `main` 的东西一行都不会上线，而部署脚本会照常打印「部署完成」** —— 它成功地把旧站又装了一遍，没有任何报错。

上线前跑 `python scripts/preflight.py`（不碰生产、不改任何东西），部署后跑 `ops/verify.sh`（同样只读）。

写这类 shell 抽查脚本有两条一定要守：

- **不要写 `echo "$x" | grep -q`。** `grep -q` 一匹配上就退出并关掉管道，上游 `echo` 拿到 SIGPIPE 死掉（141），而 `set -o pipefail` 把整条管道判成失败 —— 「匹配成功」被读成「没找到」。谁先跑完是竞态，所以**时好时坏**：同一份脚本同一个页面，第一次全绿、第二次全红。用 herestring：`grep -q -- "$pat" <<<"$var"`。
- **「文件存在」证明不了部署成功。** `/srv/heuesta/static` 是持久卷，`ManifestStaticFilesStorage` 从不删旧哈希文件，目录里躺着好几个月前的同名文件。要验**引用关系**：从服务出来的 HTML 里抠出哈希，再比对磁盘那份与仓库那份的大小。
- Windows 上写的 `.sh` 要过一遍 `python scripts/fix_lf.py`：BOM 会让内核找不到解释器，CRLF 会让每个比较值多一个 `\r`。`.gitattributes` 的 `eol=lf` 只管入库与签出，而 `scp` 是二进制拷贝 —— 工作区什么样服务器上就什么样。**也不要用 `Get-Content | ssh` 喂脚本**，PowerShell 管道会按控制台编码重编码内容，UTF-8 注释被搞坏、连引号配对一起坏掉。用 `scp`。它的第 1 项就是这件事，另外还查：缺不缺迁移、prod 设置下 `check --deploy` 有无预期外告警、静态管线、`requirements.txt` 没混进开发工具、`env.example` 覆盖全部**没有默认值**的环境变量（少一个容器直接起不来）、`deploy.sh` 引用的文件都在、该入库的产物没被 `.gitignore` 挡掉、字体子集跟得上模板。

- **第三方 app 会改 settings，读源码看不出来。** `django-simpleui` 在 `ready()` 里无条件把 `XFrameOptionsMiddleware` 从 `settings.MIDDLEWARE` 里 pop 掉（它的后台靠 iframe），于是 `base.py` 里那一行看着好好的、运行时不在，**整站不发 X-Frame-Options**。这个头现在由 nginx 发 `SAMEORIGIN`。怀疑某个设置没生效时，别读源码 —— 打印 `settings.XXX` 或跑 `check --deploy`。
- **明确接受两条 `check --deploy` 告警**（理由在 `preflight.py` 的注释里）：不开 HSTS（打开后浏览器长期记住「只走 HTTPS」，证书出问题时不能退回 HTTP 救场）、不开 `SECURE_SSL_REDIRECT`（nginx 已经在做，重复做的收益为零而配错代理头就是重定向死循环）。加新的告警要么修、要么写进那份清单说明理由，不要靠「反正一直是黄的」放过去。
- 部署**不含备份**，先跑 `ops/backup.sh`。
- 生产是 2 核 1.6G，`docker compose build` 就在上面做，留出时间。
- `/opt/heuesta/.env` 里 `EMAIL_HOST_USER` 没配的话验证码只打进 docker 日志 —— 招新期间等于注册链路瘫掉。
