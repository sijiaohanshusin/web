# 排版与质感增强计划

2026 招新版已上线（见 `docs/2026改版计划.md`）。这一份接着它做，针对两个反馈：

1. **动效与配色已经够了，但文字太单一，整站因此显得单薄。**
2. **美术零件太少** —— 没有符合协会风格的独立装饰、背景之类的东西。

两条约束（用户已定）：

- **展示效果优先于加载时间**，体积不设硬上限（重复访问有一年 immutable 缓存兜着）。
- 这个站主要用来展示，所以「好看」这件事本身就是功能。

下面的诊断不是感觉，是从 `tokens.css` + `core.css` + `home.css` 和
`app/static/` 的实际文件里数出来的。

## 诊断：现在的排版是「一个声音、三个音量」

### 数据

| 属性 | 声明次数 | 取值种数 | 实情 |
| --- | --- | --- | --- |
| `font-size` | 272 | **51** | 前 12 名全部落在 11.5–16px；约 165 处挤在这 4.5px 宽的带子里 |
| `font-weight` | 88 | 7 | 中文标题字体**只有 900 一个字重** |
| `font-family` | 70 | 6 | mono 51 次、display 15 次，**正文没有任何自托管字体** |
| `line-height` | 67 | **20** | 1.6 / 1.65 / 1.7 / 1.75 / 1.8 各有一批 |
| `letter-spacing` | 52 | 16 | 唯一一处「变化是有意的」：mono 的 1/2/3/4/8px 字距 |

零命中：`italic`、`small-caps`、`::first-letter`、`::first-line`、`text-indent`、
`font-feature-settings`、`text-wrap`。

### 51 个字号不是丰富，是没做决定

13 / 13.5 / 14 / 14.5 / 15 / 15.5px 是六个取值在干同一件事 —— 肉眼分不出来，
却让版面失去了「这两块地位不同」的能力。真正缺的是**中间层**：
17–32px 这一段几乎是空的，于是每一页都读成「一个巨标题 + 一片 13px 灰字」。
巨标题（34–96px）和小字之间没有台阶。

### 中文只有一个字重，所以「强调」只有两种：喊，或者假粗

`--font-display` 是思源黑体 **Heavy 单字重**。而 CSS 里有 33 处 `font-weight: 700`、
19 处 `600`、13 处 `800` —— 落在中文上时浏览器只能**合成假粗**，也就是这套设计
一开始明确要摆脱的「微软雅黑伪加粗」。它只在 900 那一档摆脱了。

### 最大一处：正文的声音是访客操作系统给的

`body` 用的是裸系统字体栈。也就是说**站上读得最多的那部分文字，是唯一没被设计过的**
—— Mac 上是苹方，Windows 上是微软雅黑，两个访客看到的是两个不同气质的网站，
而且都不是我们定的那个。这是「单薄」的头号来源。

### 长文页面几乎没有排版

`.md-body`（公告与活动正文共用）总共 18 条平铺规则：一个字号 15.5px、
标题 24/20/17、一个引用块、一个代码块、一个表格。而新生指南近 9000px、
公告是 Markdown —— **读者真正花时间的两处，恰好是排版投入最少的两处**。

---

## 方向 A：字体资产（其余全部依赖它）

这一层不动，B/C 都只能在现有材料里打转。

> **体积预算：已定为「展示效果优先，不设硬上限」。**
> 理由（用户口径）：这个站主要用来展示，展示效果比加载时间重要；重复访问有
> 一年 immutable 长缓存兜着。所以下面凡是「用体积换效果」的地方一律选效果。
> 仍然要守的两条底线不变：`font-display: swap` 保证文字不被字体卡住；
> `check_perf.py` 的预算数字**上调而不是删掉** —— 它的作用从「压体积」变成
> 「防止无意中多拖进来一份没人用的东西」。

- **A1 给正文一套自托管中文字体。** 现在完全没有，这是「单薄」的头号来源。
  既然不设体积上限，就**直接放宽到常用 3500 字以上**（甚至全字库），
  不要再按模板扫字 —— 正文缺字会在一段话里混进两种字形，比标题缺字难看得多，
  而公告、活动、作品简介这些内容是站务以后随时写的，模板扫不到。
  建议思源黑体 SC 的 Regular + Medium 两档，或直接上可变字重版本。
- **A2 给标题补一个中间字重**（Medium/Bold）。有了它，「强调」才不必在
  「假粗」和「Heavy 900」之间二选一。
- **A3 引入第二种声音 —— 一款衬线或高对比显示字体，只用在极少数位置**
  （拉引言、大数字、章节序号）。**这是性价比最高的一步**：用量小 → 子集极小
  （几十 KB），但「气质单薄」立刻改观，因为它带来的是**种类**的对比，
  而不是又一个字号。现在全站只有几何无衬线 + 等宽两种，温度是平的。

## 方向 B：把 51 个字号收敛成一套阶梯

- **B1 定义 type scale 令牌**（8 档左右），把 272 处声明映射上去。
  改完用 `python scripts/css_audit.py --before X --after Y` 证明没丢规则。
- **B2 补齐中间层级**（17 / 20 / 24 / 28px 这一段现在是空的）。这是
  「巨标题 + 一片小字」最直接的解药。
- **B3 行高与字距收敛成令牌**（现在 20 种行高、16 种字距）。字距那 16 种里
  mono 的 1/2/3/4/8px 是有职责的，保留；正文那几种噪音收掉。
- **B4 度量与混排**：正文行宽（measure）、中英混排的标点挤压
  （`font-feature-settings`、`text-spacing-trim`）、标题用 `text-wrap: balance`、
  正文用 `pretty`。这几条几乎零成本，但「精致度」提升很明显。

**判据**：每一档字号都要能说出它的职责。说不出来的就是噪音，删掉。

## 方向 C：长文排版（读者真正停留的地方）

- **C1 `.md-body` 升级**：标题层次、引用块（现在只有一种）、图注、边注/脚注、
  代码与公式、表格。这一份被公告和活动详情共用，改一处收益覆盖两类内容。
- **C2 新生指南**：章节导语、拉引言、元件参数表、公式排版 ——
  正文里 `V = I × R` 现在是纯文本，而这是一个电子科技协会最该讲究的地方。
- **C3 文本级装饰**：首字下沉或首行处理、序号引导、小型大写字母跑英文缩写。
  克制着用，一页一处。

## 方向 D：美术零件（这一块最缺，而且最不受「没照片」限制）

### 先看清库存

全站**自有美术资产只有一个文件**：

| 有的 | 数量 |
| --- | --- |
| `brand/logo-mark.svg` | **1 个**，4KB。唯一一份自有矢量图形 |
| `includes/icon.html` 里的线性图标 | 19 个，全部 1.7 描边、24 viewBox、一种风格 |
| `img/recruit/` | 69 张**参考图鉴**（元件棚拍 + 软件截图），不是装饰件 |
| `img/carousel/` | 5 张照片 |
| favicon / logo / og-card / 二维码 | 5 个 PNG，功能件 |

其余所有「看着有设计」的东西，其实都不是美术资产：

- `.nf-scope` / `.scope-grid` 示波器网格 —— 两层 CSS 渐变，**全站唯一一种底纹**
- 页脚那道波形 —— 一条内联 SVG path，**全站唯一一处区块过渡**
- 走线 / 焊盘（时间轴、路线图、目录、等级阶梯、报名进度）—— 全是 div + border 拼的
- 空焊盘占位框的四角定位标 —— 一套记号，反复用
- 3D 会标、Hero 粒子场 —— 动效，静止时不产生层次

**结论**：丰富度全压在动效和颜色上。页面**静止**的那一刻，可看的东西很少 ——
这正是「整体单薄」的来源。而且底纹只有一种、区块过渡只有一处，所以还叠加了「单一」。

### 关键判断：缺照片挡不住这件事

协会缺照片，而且会缺一段时间。但**这套设计语言恰好是可以「生成」的** ——
PCB 是几何的：走线、焊盘、过孔、丝印、阻焊、开窗、覆铜。这些东西不需要相机，
用矢量与程序就能画，而且画出来天然就是协会自己的样子，不是找来的素材。

**这是这个项目少有的、能完全在内部解决的资产缺口。** 优先做它，比等照片划算。

### 缺什么（按性价比排）

- **D1 底纹系统**（现在只有一种）。同一套「电路板」语汇可以分出好几层质感：
  裸基板、覆铜区、阻焊开窗、丝印层、过孔阵列、蚀刻走线场。不同区块用不同层，
  页面立刻有了「这一段和上一段不是一回事」的分别。
- **D2 区块过渡件**（现在只有页脚一道波）。黑白区交界现在是硬切。可以做一组
  过渡：走线穿过分界、阻焊边缘的锯齿、丝印虚线、焊盘骑跨切口。
- **D3 边饰与工艺记号**。四角定位标只用在空槽位上，其实是可复用的语汇 ——
  卡片角标、章节起止记号、引言的引脚符号、页码的丝印编号。
- **D4 技术插画（最能提升「厚度」，也最贴协会身份）。** 零基础的现状是：
  整站没有一张示意图。而新生指南在讲欧姆定律、运放、滤波器、STM32 —— 这些
  都该有图。原理图片段、元件剖面、信号波形、频响曲线、引脚定义图。
  **这是内容与美术同时补齐的一步**，而且只有电子科技协会会有这种图，
  别人抄不走。
- **D5 数据可视化件**。表头盘、指针表、示波器扫迹、频谱、史密斯圆图 ——
  用来承载参数、成绩、规格。协会的数字素材是天然的。
- **D6 空态与占位的第二套设计**。空焊盘占位框是好设计，但全站只有这一种，
  出现太多次。按位置分几种（人像位、作品位、证书位、视频位）。
- **D7 质感层**。现在是纯平的黑。基板颗粒、阻焊的哑光反光、覆铜的方向性光泽、
  丝印油墨的轻微不匀 —— 极低不透明度的噪声/纹理，静止时的「厚」大半来自这里。
- **D8 图标集扩容与分层**。19 个图标一种风格一种描边。缺：填充变体、双色变体、
  大尺寸装饰版（章节头用）、以及元件符号的完整一套（电阻/电容/电感/二极管/
  三极管/运放/MCU/晶振/接插件）—— 后者同时能喂 D4 的插画和图鉴。

### 我能做到哪一档，哪一档需要人

说清楚免得预期错位：

- **能做好**：几何/技术/程序化的东西 —— 底纹、过渡件、边饰、原理图片段、
  元件符号、波形与曲线、数据可视化件、噪声纹理。这类图是**规则驱动**的，
  可以用代码生成 SVG 并写校验脚本（`verify_logo.py` 就是这个套路：
  正反向保真 + 焊盘内孔不许被填）。会标本身也是这么做出来的。
- **做不好**：手绘感的插画、吉祥物、有笔触和情绪的图像。那类需要真正的设计师
  或美术，我做出来会僵。**如果想要这一路，得找人。**

好在这套设计语言要的正好是前一类。

## 不做的事

- 不加第四个字体家族。三种（正文无衬线 / 等宽 / 第二声音）到顶。
- 不为了变化而变化。新增的每一档字号、每一处装饰都要有职责 ——
  美术零件尤其容易失控，多加一层底纹很爽，加到第五层就是噪音。
- **不用来源不明的素材**。所有装饰件要么自己生成、要么是明确许可的开源资源，
  并在 `app/static/brand/README.md` 里记许可。这一条和字体一样严。
- 不动亮色主题这条底线（见 `.kiro/steering/改版约定.md`）。
- 不为了「有插画」去画和电子无关的图。协会的身份是插画的题材来源，
  不是拿插画去装饰一个通用网站。

## 顺序建议

体积不再是约束之后，顺序按「见效速度 × 是否为后面打地基」排：

1. ~~**D1 + D2 + D7**（底纹分层、区块过渡、质感层）~~ —— **已完成**，见下面
   「第 1 步实况」。静止时的层次立刻不一样，而且不碰内容、不碰模板结构，风险最低。
2. ~~**B1 + B3**（字号阶梯、行高与字距收敛）→ **B2**（给中间层派活）~~ ——
   **已完成**，见「第 2 步实况」。B2 刻意拆成第二个提交：那是逐组件的设计决定、
   要一页一页截图看，混在 387 处机械替换里出问题分不清是谁。
3. ~~**A1 + A3**（正文字体 / 第二声音）~~ —— **已完成**，见「第 3 步实况」。
   **A2（标题中间字重）实测之后降级为暂不做**，理由在那一节里。
4. **C1 + C2**（长文排版）—— 前三步的材料在这里才真正花出去。
5. **D8 + D4**（图标集扩容 → 元件符号 → 技术插画）—— 量最大、最慢，
   但也最能长期区别于别人。可以按新生指南的章节顺序分批做。
6. **D3 + D5 + D6 + B4 + C3** 收尾细节。

前三步做完就该重新截图给你看一轮，再决定 D4 投多少。

## 第 1 步实况：D1 底纹分层 + D7 质感层 + D2 区块过渡（已完成）

全部在 `tokens.css` 里，模板只加类名。**没有新增任何图片文件**。

### 做了什么

| 件 | 类名 | 用在哪 |
| --- | --- | --- |
| 裸基板（玻纤斜织） | `.surf-weave` | `#nf-forge`、`.site-footer` |
| 覆铜（细斜纹） | `.surf-hatch` | `#nf-honors` |
| 过孔阵列 | `.surf-via` | `#nf-roadmap` |
| 丝印刻度 | `.surf-silk` | 备用（边缘/页边用，暂未上） |
| 基板颗粒 | `.grain` | `#nf-forge`、`.site-footer`、`.page-hero::after` |
| 邮票孔过渡件 | `includes/edge.html` | 首页 6 处黑白交界 |

示波器网格仍是 `.nf-scope`，不并进这一套 —— 它是「仪器屏幕」不是板材。

### 几个当时没想到、做完才成立的结论

**表面必须画在伪元素上，不能加到元素自身的 `background`。** `.nf-dark` 用
`background:` 简写、`.nf-light` 自己占着 `background-image`（坐标纸），直接加会被
擦掉或者抢属性（这个坑全站已经踩过四次，见 steering）。更关键的副作用是好的：
伪元素**不在** `check_a11y.py` 「逐层向上找不透明背景」那条链上，所以对比度检查
完全没受影响（`/` 仍量到 10 个、`/news/` 6 个、跳过仍是 1）—— 计划里担心的
「底纹会让对比度检查从『量到了』变成『跳过』」没有发生。

**代价是一个区块只能有一层表面。** `::before` 归底纹、`::after` 归颗粒，而
`.nf-scope` 也用 `::before` —— 所以 `.nf-scope` 和 `.surf-*` 不能叠在同一个元素上，
后者会被吃掉。这个限制反而是对的：两层材质加颗粒已经是噪音而不是层次。

**边缘渐隐用 `mask-image` 做在同一个伪元素上**，不再叠第二层渐变。旧的
`.nf-scope::before` 是把 `var(--black)` 写死在渐变里，换个底色就露出一条生硬的边。

**颗粒用 SVG `feTurbulence` 的 data URI**（提成 `--grain-img` 令牌，`core.css` 的
`.page-hero::after` 复用同一份）：任意 DPR 都清晰、零额外请求、确定性。不加到
`body` 上 —— z-index 会和固定导航（100）、加载动画（300）打架。

**过渡件的母题是邮票孔（拼板断桥孔）**，语义正好是「一块板从另一块上掰下来」。
用 `radial-gradient` 而不是 SVG：SVG 要 `preserveAspectRatio="none"` 拉伸才能铺满
任意宽度，那会把圆孔压成椭圆（页脚那道波是纯 stroke 曲线，拉伸看不出来，孔会）。

**实心到透明之间必须留 `.6px` 过渡。** 第一版写的是 `0 99%, transparent 100%`，
半径 4.5px 下那 1% 不到 0.05px，浏览器没有抗锯齿的余地 —— 半圆被光栅化成方齿，
放大 8 倍一眼看出。孔距定 17px、半径 4.5px：拉宽到 26px 会读成城堡齿
（castellation），是另一种工艺、另一种意思。

**荣誉段与学习资源段刻意不加过渡件。** 它们的上一个区块是黑还是白，取决于
`featured_works` / `featured_honors` 两个 `{% if %}` 的组合。写条件判断能对，但
「装饰件的参数依赖另一个区块的渲染条件」迟早会在加区块时悄悄错掉，而方向写反的
后果是孔和自己这块同色、整条看不见且不报错。留白比留一个会烂掉的条件好。

**`prefers-contrast: more` 下摘掉表面与颗粒，但保留过渡件** —— 后者标的是结构
（区块边界），不是装饰。

### 踩到的坑

**`.nf-scope > *` 那一类规则会把 `.edge` 的 `position` 按回 `relative`。**
`.nf-scope > *`（core.css）、`.surf-weave|hatch|via > *`、`.grain > *` 都写着
`position: relative; z-index: 1`，用途是把内容提到材质层之上；它们和单个 `.edge`
同为 (0,1,0) 特异性，而 core.css 在 tokens.css 之后加载 —— 于是挂了 `.nf-scope` 的
区块里，过渡件掉进常规流、被区块的 `padding-top` 推到区块**内部**。它照样把一排孔
画得好好的，所以这不是「不见了」而是「跑到区块中间去了」：分镜 02 那块的
padding-top 正好 240px（`.nf-bridge + .nf-section`），整条孔就落在大数字上方一片
黑里。修法是把选择器写成 `.edge.edge` 提一级特异性。

**这个坑是断言抓出来的，不是眼睛。** 之前肉眼确认过 1:1 和 8 倍放大都对 ——
看的是白区那条（`.nf-bridge`，没有 `.nf-scope`，位置本来就对）。给
`check_hero.py` 加了三条断言之后立刻红：孔色 == 上一个 section 的底色、
孔色 != 自身底色、**每条都压在自己区块的顶边上**（第三条抓到了它）。

**`css_audit.py` 现在支持 `git:REF:path`。** Windows 上
`git show HEAD:x.css > before.css` 会被 PowerShell 写成 UTF-16，脚本读它直接
`UnicodeDecodeError`。

### 这一轮的验证结果

390 个 Django 测试、`check_static_pipeline`、18 个浏览器脚本串行、
`motion_smoke`、`verify_logo` 全绿；`css_audit` 对 `tokens.css` 丢失 0 · 变化 0；
桌面与移动端（DPR 2）都放大看过分界线 —— 移动端的半圆更圆（像素多一倍）。

## 第 2 步实况：B1 字号阶梯 + B3 行高字距收敛（已完成）

令牌全部在 `tokens.css` 的 `:root` 里（带职责表注释），四个样式表一起改。
守门的是新脚本 `scripts/type_audit.py`。

### 收敛结果

| | 之前 | 之后 |
| --- | --- | --- |
| `font-size` | 315 处声明 / **51 种取值** | 343 处 / **22 个令牌**（14 固定 + 8 流体） |
| `font:` 简写里的字号 | 28 处，**上面那 51 种没数到它们** | 全部改成 `var()` |
| `line-height` | 75 处 / **20 种** | 75 处 / **6 个令牌** |
| `letter-spacing` | 59 处 / **16 种** | 59 处 / **9 种**（只收噪音，不建令牌） |

固定档：11 / 12 / 13 / 14 / 15 / 16 / 18 / 20 / 22 / 26 / 30 / 36 / 50 / 64。
小号那一段刻意 1px 一档 —— 这个尺寸下 1px 已经是 6~9%，是能看出来的一档；
再细分就回到 51 种的老路。流体档把 21 条各不相同的 `clamp()` 收成 6 条 + 1 条导语。

**归档规则是「就近 + 说得出职责」，实际像素移动一律 ≤7%。** 唯一往下归的特例是
顶层导航（14.5 → 14，不是 15）：整行链接 726px、容器最宽 1240px，只剩 10px 余量，
往上归会多出约 25px，直接把「新生指南」挤成两行。

### 这一步的关键工具：`css_audit --resolve-vars`

把 387 处字面值换成令牌时，字面比较会报出 300 多条「13.5px → var(--fs-sm)」——
等于没有报告，而这次改动的**全部风险恰好在「哪几处的实际像素值动了」**。
所以给 `css_audit.py` 加了 `--resolve-vars`：比较前先把 `var()` 按 `:root` 展开，
于是报告里剩下的就只有真正移动过的那些，并按 `(前值 → 后值)` 归组：

```
丢失 0 · 变化 233 · 新增 28        ← 新增的 28 条全是令牌定义本身
font-size    13.5px -> 14px   × 35
font-size    12.5px -> 13px   × 30
font-size    14.5px -> 15px   × 19
font-size    14.5px -> 14px   × 3     ← 导航那三条
line-height  1.8    -> 1.85   × 10
...
```

顺带把 `--before` 改成可以给多个文件（`--resolve-vars` 需要 tokens.css 一起进来，
否则令牌查不到值）。

### 踩到的坑

**`font:` 简写把字号藏起来了，第一版检查报「全部走令牌」却漏了 28 处。**
`font: 700 11px/1 var(--font-mono)` 里有字号也有行高，而逐属性扫 `font-size`
永远看不到它们 —— 于是 `type_audit.py` 一开始理直气壮地打印
「font-size 315 处，全部走令牌」，同时全站还有 28 个 mono 小标签在用字面值。
是 grep 字距时偶然看见的。现在 `type_audit.py` 单独检查 `font` 简写里的 `px`，
写法是 `font: 700 var(--fs-3xs)/var(--lh-flat) var(--font-mono)`（`var()` 在简写里
合法，已在浏览器里量过：`.reg-channel-kicker` 得到 11px/11px/2px）。

**不要用「整文件读出来 → 正则替换 → 整文件写回」改 Python 源码。**
`Get-Content -Raw | ... | Set-Content -NoNewline` 把 `check_perf.py` 写坏了
（70 增 91 删，注释行被合并成一行，`IndentationError`）。改一个数字就用编辑工具
改那一处；批量改 CSS 用带解析的脚本（本步骤那份一次性脚本用完即删）。

**`check_perf.py` 的内页 CSS 预算 150 → 175 KB。** 涨的几乎全是 tokens.css 里的
设计说明注释（未压缩要算进来，gzip 后线上增量是个位数 KB）。按计划**上调而不是
删掉**：这条断言的作用从此变成「防止无意中多拖进来一份没人用的东西」。

### B2：给中间层派活（第二个提交）

阶梯建好只是「可以用」。18 / 20 / 22 三档当时只有 34 处在用，而
「一个巨标题 + 一片 13px 灰字」的观感靠的正是这三档 —— 所以单独走一轮，
判据两条：

1. **标题不许和正文同号。** 原来 `.hn-title`(15) / `.tm-name`(16) /
   `.event-card-title`(16) / `.dash-panel h2`(16) / `.fb-mine h2`(16) 都落在
   正文那一档上，只靠字重和颜色区分 —— 那正是「文字样式单一」的字面意思。
2. **同一角色跨页面必须同号。** 卡片主标题原来有 15 / 16 / 18 三种。

一共动了 27 处（`css_audit --resolve-vars`：丢失 0 · 新增 0）：

| 角色 | 之前 | 之后 |
| --- | --- | --- |
| 列表卡片主标题（公告 / 作品） | 18 | **20** |
| 卡片主标题（活动 / 项目 / 成员 / 资源 / 首页公告条） | 16 | **18** |
| 面板与段落标题（`.panel h2` / 折叠块 summary / 时间轴节点 / 视频标题） | 16~18 | **18~20** |
| 招新落地页段落标题 | 20 | **22** |
| 长文 `.md-body` h1 / h2 | 26 / 20 | **30 / 22** |
| 荣誉行奖项名 | 15 | **16** |

荣誉行只升一档（不是两档）：那是一年十几行的密排清单，升两档整页会高出一屏。

**顺带给 `--fs-lead` 派上活。** 它原来只服务首屏副标题一处，现在所有页头说明、
作品导语、注册页导语都用它（`.page-hero-sub` / `.rec-hero-sub` / `.recruit-hero p` /
`.wk-detail-lede` / `.auth-lede` / `.nf-join-sub`）—— 导语是「比正文大一档、
行高更松、行宽掐在 720px」的一种角色，而流体值让它窄屏 15px 不挤、宽屏 18px 撑得住。
这也是「一档必须有职责」的正面例子：之前它只有一个使用者，其实是没定义清角色。

### 明确没做的

- **`letter-spacing` 不建令牌**，只把用一次的噪音值（.3 / .8 / 1.4 / 1.6 / 2.4 / 2.5px）
  折进邻近档，收成 0 / .5 / 1 / 1.5 / 2 / 3 / 4 / 8px 八档。理由：mono 的字距是
  逐处的语义（同一个 11px 标签，1px 和 3px 是两种气质），给它们起 `--tr-1`…`--tr-7`
  这种名字没有信息量，只是把字面值换成代号。
- **`font-weight` 一个字没动。** 88 处里 600 / 700 / 800 落在中文上全是合成假粗，
  但那要等第 3 步的真字重（Medium / Bold）到位才有意义 —— 现在改只是换一个假粗。
- **B4（行宽、标点挤压、`text-wrap: balance`/`pretty`、`font-feature-settings`）
  留到收尾那一批**，它们和第 3 步的字体资产强相关（挤压和字距调整要看真字体的
  度量），现在做等于对着系统字体调。

## 第 3 步实况：A1 正文自托管中文（已完成）

### 先量了一遍，才知道该花多少字节

用浏览器数首页上「自己带文字的元素」各用什么字体：

| 家族 | 元素数 | 说明 |
| --- | --- | --- |
| 系统栈（`-apple-system` 起） | **135** | 占绝大多数，全靠访客的操作系统 |
| JetBrains Mono（自托管） | 54 | 数字与编号，已经是自己的 |
| ESTA Display（自托管 Heavy） | 17 | 标题 |

这就把优先级问过了：**正文是站上读得最多的文字，也是唯一没被设计过的那部分**。

顺带纠正计划里一句想当然的话。原来写的是「CSS 里 33 处 700、19 处 600 落在中文上
只能合成假粗」—— 实测**不是**：`--font-display` 只有 900 一档，浏览器按字体匹配
规则会选那一档（不合成），而正文走系统黑体，微软雅黑本来有真 Bold。首页 17 个
用标题字体的元素里只有 1 个写了非 900 的字重。所以 A2 的价值不是「修假粗」，
而是「让标题能有一个安静的字重」—— 优先级因此下调，排在 A3 之后。

**真正的合成假粗风险出现在自托管正文之后**：只自托管 Regular 的话，`<strong>`
与 700 会让浏览器把 Regular 描粗，而系统黑体本来有真 Bold —— 自托管反倒变差。
所以两档成对是硬要求，`check_fonts.py` 有一条断言专门钉「两档覆盖逐字一致」
（不一致只会在被加粗的那几个字上掉档，是最难发现的那一类）。

### 做了什么

| 文件 | 字表 | 体积 |
| --- | --- | --- |
| `SourceHanSansCN-Regular-subset.woff2` | GB2312 一级字 ∪ 模板用字 = 3760 字 | 1030 KB |
| `SourceHanSansCN-Bold-subset.woff2` | 同一份字表 | 1041 KB |

- 新增 `--font-body` / `--font-sys` 两个令牌：`body` 用前者，系统栈退到兜底。
  `--font-display` 的兜底也插入了 `ESTA Sans` —— 标题缺字时退到**自己的 Bold**
  （同一套设计、差一档字重），而不是跳到系统黑体（换一套字形）。
- **字表取 GB2312 一级字全集，不按模板取字。** 标题的用字是固定的（内容作者改不到
  标题），而正文要承载站务以后随时写的公告、活动、作品简介、成员姓名 —— 模板扫不到。
  字表从 Python 自带的 `gb2312` 编码枚举出来：确定、离线、可复现，不依赖某个网页上的
  「常用 3500 字表」哪天改了内容。
- 四个字体全部 `preload`。首访字体合计约 2.5MB，明确是用体积换效果（用户口径 +
  一年 immutable 缓存 + 前面挂 EdgeOne）。`check_perf.py` 的 font 预算 500 → 2600KB、
  首页「代码+字体」900 → 3000KB，**上调而不是删掉**。
  嫌重的话下一步是按 `unicode-range` 切片，**不是砍字表** —— 砍字表换来的是
  「某些字突然变成另一种字体」，又一个静默故障。

### 顺手修掉一个真 bug：按钮里的中文不是用站内字体画的

`<button>` 不继承 `font-family`（UA 样式表写死 `font: 400 13.33px Arial`）。
于是**每一个带文字的按钮都在用 Arial 画中文** —— Arial 没有汉字，Windows 会退到
宋体，也就是全站唯一一处衬线体，出现在按钮上。实测「复制群号」那个按钮就是
`font-family: Arial`。英文界面上完全看不出来，所以这类漏洞能活很久。
修法是一条 reset：`button, input, select, textarea, optgroup { font-family: inherit }`。

### A3 第二声音：宋体，只服务「导语」这一个角色

全站原来只有「几何无衬线 + 等宽」两种声音，温度是平的。加的是**种类**上的对比，
比再加一档字号有效得多。

选思源宋体 SemiBold（OFL，与正文同源）。只做一档，因为宋体的横画在纯黑底上本来
就细，Regular 会发虚；而它的用途全是「大一号的短句」，不需要字重变化。

**字表按模板取字（977 字，461 KB），不是正文那份 GB2312 全集。** 先按全集做了一版：
1456 KB —— 宋体轮廓比黑体复杂，同样 3760 字要多花 40%。代价是**它只能用在模板
文案上**：站务写的内容里可能有子集外的字，那会在一段话里混进一个黑体字。
所以 `.wk-detail-lede`（作品简介，会员自己写的）刻意留成黑体，CSS 里写了原因 ——
这条约束没法靠脚本证明，只能靠注释挡住「顺手统一过去」。

用在哪：`.page-hero-sub`（每页页头）、`.recruit-hero p`、`.rec-hero-sub`、
`.auth-lede`、`.nf-join-sub` —— 全是同一个角色。于是每一页的页头都变成三个声音：
mono 的 eyebrow → Heavy 黑体的大标题 → 宋体的那句说明。

窄屏也没问题：`--fs-lead` 在手机上是 15px，但手机 DPR≥2，实际像素比 1x 桌面的
18px 还多（截图确认过，比桌面更扎实）。

### A2 标题中间字重：降级为「暂不做」

原计划把它排在 A1 之后。实测之后不做了：`--font-display` 只有 900 一档，而首页
17 个用它的元素里只有 1 个写了非 900 的字重 —— 也就是说「假粗」这个问题不存在
（浏览器按匹配规则选 900，不合成）。真正缺的是「安静的标题字重」，而**正文的
Bold 档已经能承担那个角色**（`--font-display` 的兜底里就有它）。
再加一档 Heavy 之外的标题字重要多 300~400KB，而现在没有一处设计需要它。
等哪天真有「标题要小声说话」的需求，再从这里接着做。

### 验证

391 个 Django 测试（新增 1 条：正文字体不许交给操作系统）、`check_fonts.py`
新增 9 条正文断言（两档体积、GB2312 全覆盖、模板用字全覆盖、两档覆盖一致）、
19 个浏览器脚本 + `motion_smoke` + `verify_logo` 全绿；浏览器里确认
`document.fonts` 四个 face 全部 loaded、`body` 计算值是 `ESTA Sans`、
正文 `font-weight: 400` 走的是 Regular 档；放大 3 倍确认加粗是真 Bold 不是描粗。

`ops/verify.sh` 与 `preflight.py` 里「两个字体」的地方一起改成四个 ——
这类写死数量的抽查不改就会在部署后报假红。

## 第 4 步实况：标题制版（用户反馈「艺术性不足」之后的返工）

第 2、3 步做完，用户的反馈是：**「大部分还是看起来像微软雅黑或者黑体，艺术性不足」。**
这个判断是对的，而且不是 bug —— 先查了线上响应头（`cache-control: private, no-cache`、
`eo-cache-status: MISS`、`age: 0`），他看到的确实是新版。问题在于**思源黑体本身就是
黑体**，和微软雅黑、苹方同属现代几何无衬线，自托管换来的是「所有访客看到同一套字」，
不是气质；而字号阶梯那一步的移动我刻意压在 7% 以内，本来就是为了不改观感。

**气质由标题字形 + 版面构成决定，而标题当时用的思源 Heavy 恰好是最中性的一款。**

### 做了什么（三层，按贡献排序）

**① 器械层（贡献最大，零资产）。** `.nf-eyebrow` 原来只是一行 mono 小字，现在带
一段刻度尺（细刻度 + 每三格一根主刻度）和一条带端标的尺寸线，全用伪元素画。
改一处，全站 14 个调用点一起器械化，模板一个字没动、无障碍树不变。
标题从「一行字浮在黑底上」变成「装在仪器面板里」。

**② 字形层。** 标题字换成**得意黑**（Smiley Sans，SIL OFL）—— 倾斜 + 紧缩的展示体，
替掉最中性的思源 Heavy。按同一份模板字表取字后 270KB < Heavy 的 333KB，**一进一出
体积还降了 63KB**，覆盖 9440 码位。全站标题字距从 +1px 改成负值（正字距是给方正
字形留的，紧缩体上会散架）。

**③ 工艺层（克制）。** 首屏两行各开**一道**横向阻焊窗，第二行句尾挂一个焊盘 + 引线
（语义同会标的 pad-out）。都用 mask 与伪元素做，不动 `color`，所以对比度照旧量得到。

### 建完又否决的三个方案（都是做出来看了才否决的）

- **45° 密斜纹铺满字面**：那是把字填成纹理，不是工艺。可读性掉得很明显，78px 勉强、
  48px 糊成一片。**稀疏才读得出是工艺** —— 最后只留一道横窗。
- **铜面渐变**（`background-clip: text` + 金属渐变）：要把 `color` 设成 `transparent`，
  于是 `check_a11y.py` 的对比度直接量不到，而且所有 `currentColor` 的细节（焊盘环）
  会一起变透明。为这两条否决。
- **手工走线字做整句标题**：写了生成器（`scripts/build_lettering.py`，与会标同一套
  坐标系与线宽），一、个、电这类简单字很漂亮，但**等宽走线放不下 10 笔以上的字** ——
  「想」13 笔要 7 条平行横画，96px 里 8px 墨 + 8px 缝 × 7 = 112px，比字面本身还高。
  这是物理约束，不是手艺问题。**结论：走线字用在笔画极少的地方 —— 数字。**
  （下一步就是做「科协专属数字」，用户也提了「那个 31 不好看」。）

### 两个静默坑

**`.line-reveal { display: block }` 把 `.nf-eyebrow` 的 flex 按掉了。** 它在 core.css
里排在后面、同特异性，于是首屏那条同时带 `.line-reveal` 的 eyebrow 运行时不是 flex，
两个伪元素退回 inline、**width/height 被直接忽略**，刻度与尺寸线一个都没画出来 ——
而页面照常渲染、控制台干净。这套 eyebrow 有 14 处调用、父容器各不相同，所以最后
让记号本身与父级 display 无关（`inline-block`），而不是去猜谁会覆盖。
和上一步 `.edge` 被 `.nf-scope > *` 按倒是同一类错误。

**会闪的光标当引线用，有一半时间是断的。** 先试过让首屏那个 `_` 当焊盘的引线，
但它是 `step-end` 闪烁 —— 灭的那半个周期里焊盘环孤零零悬在半空。移动端截图逮到的。
最后收尾记号只留焊盘，闪烁改由焊盘自己呼吸。顺带：删掉 `@keyframes caret-blink`

## 验证要求

排版与底纹改的是 `tokens.css` 与 `core.css` 两个全站文件，所以每一轮都要：

- `python scripts/css_audit.py` 证明没丢规则
- `python scripts/check_fonts.py`（改了文案或字体一定要跑；缺字会静静回退系统黑体）
- 改了模板文案重跑 `python scripts/build_fonts.py`
- **全部浏览器检查脚本串行复跑一遍** + `check_a11y.py`（字号、字重、底纹都会动
  对比度 —— 底纹尤其危险：它会让「背景是纯色」的假设失效，对比度那一节会从
  「量到了」变成「跳过」）+ `check_perf.py`（预算数字上调，但不要删）
- `cd app; python manage.py test`
- 截图看，桌面与移动端各一遍。**新增底纹与装饰件必须放大看**
  （`crop.py --box ... --zoom 4`）—— 一整页图上看不出「这层纹理是不是糊了」

新增矢量装饰件另加两条：

- 每一件都进 `app/static/brand/`，并在那里的 README 记来源与许可
- 规则驱动的图形要有校验脚本，照 `verify_logo.py` 的路子写（它守的两条是
  「任何属性都要带值」和「走线不能画到焊盘圆心」）。**图形失效往往是静默的** ——
  一个无值属性能让整张 SVG 解析不出来，而页面只是少一块东西
