# 荣誉墙的数据是从哪来的

荣誉墙（`/honors/`）上那批记录不是手工敲进后台的，是 `manage.py import_honors`
一次导入的。这份文档说明来源、口径，以及要加新记录时该改哪里。

## 来源

`2025科协招新.pptx`（2025 年 9 月的招新宣讲 PPT，25 页 / 104 张内嵌图）。里面有
十几年的获奖证书照片。**这个 pptx 有 27MB，不入库** —— 和 `正面.jpg` 那几个本地
参考资料一样列在 `.gitignore` 里。要重新取的话：pptx 就是个 zip，图在
`ppt/media/`，每页文字在 `ppt/slides/slideN.xml` 的 `<a:t>` 里。

另有一张 2026 年的证书是单独给的（第九届嵌入式芯片与系统设计竞赛 全国一等奖）。

## 三条口径

**一、录进来的都是队员姓名与证书编号齐全的真实记录。** 已征得同意公开 —— 荣誉墙
上会出现队员姓名、指导教师姓名、证书编号。这一条和「把成员信息放到公开页面上必须
本人同意」是同一件事，只是同意的方式不同：团队页靠 `User.show_on_team` 开关，
这里靠事先问过。

**二、软著不算「国家级」。** `Honor.Level.NATIONAL` 的语义是国赛获奖；软件著作权
登记证书是国家版权局发的凭证，不是竞赛奖项。混进去会让荣誉墙顶部那个「国家级 N
项」变成「国赛获奖 + 别的东西」。所以它归 `OTHER`，分量由标题里的「国家版权局」
交代。

**三、两条没有证书照。** 第十八届智能车独轮车组国一、TRIZ 杯创新方法大赛国一 ——
PPT 里那两张只有 309×433，放到证书墙上是一块糊斑。奖项信息照录（PPT 正文里有），
图留空。模型注释里本来就写着「证书照片是可选的加分项，不是骨架」。

## 没有录进来的东西

PPT 里还有这些，**刻意没用**：

| 是什么 | 为什么不用 |
| --- | --- |
| 8 本教材封面、Vivado / Keil / Linux / Altium / PyTorch 商标、各赛事会徽 | 第三方版权物。元件图鉴用自绘 SVG 符号，正是为了避开这个 |
| 学生名单扫描件（含姓名 + 学号）5 张 | 隐私。学号是身份标识 |
| 微信群聊截图 2 张（含加分名单） | 隐私 + 聊天内容 |
| 几位同学的自拍与表情包梗图 5 张 | 未经本人同意的肖像，而且明显是内部玩笑 |
| 2025 年的旧招新 QQ 群二维码 | 站上现有的是当前群，放旧的会把人引错 |
| 三位学长学姐的完整履历（含均分、专业排名、保研 offer） | 学业成绩比姓名敏感得多。招新页只保留「XX 级学长，获 XX 奖」那一档 |

## 要加新记录时改哪里

1. 证书原图放 `.artsrc/certs/`（不入库，和美术资产母图同一个约定）
2. 在 `scripts/build_certs.py` 的 `CERTS` 里加一行（输出名, 源文件名），跑一次
   → 产物落在 `app/news/data/honors/*.webp`，**这个目录要提交**
3. 在 `app/news/management/commands/import_honors.py` 的 `HONORS` 里加一行
4. `python manage.py import_honors --dry-run` 看一眼，再去掉 `--dry-run`
5. **跑 `python scripts/check_content_fonts.py`** —— 人名容易带 GB2312 之外的字，
   缺字会静默回退系统黑体。它会告诉你该往 `build_fonts.py` 的 `CONTENT_EXTRA`
   里加什么（`淏` 就是这么发现的）
6. 生产上部署完再跑一次 `import_honors`（命令幂等，重跑不堆数据）

## 为什么产物要提交进仓库

`Honor.certificate` 是 `ImageField`，落在 `MEDIA_ROOT` 下，而 `app/media/` 是
gitignore 的 —— 本地导入的图**到不了生产**。所以处理后的 webp 放在
`app/news/data/honors/`（跟着代码走），由导入命令喂给 `ImageField`。
13 张合计约 1.1MB（原图 5.8MB）。
